# Evidence: what is measured, what is inferred, how to measure locally

Every claim in SKILL.md is either measured (with a source and a scope) or a mechanism inferred from measured behavior. This file is the ledger. When a claim matters for a decision, check its row before trusting it, and prefer the local protocol at the bottom over any number here.

## Measured: properties of the consumer

| Claim in SKILL.md | Finding | Source | Scope caveat |
|---|---|---|---|
| Prior knowledge tracks corpus frequency | QA accuracy rises log-linearly with the count of relevant pre-training documents; BLOOM-176B goes from 25% to above 55% accuracy as relevant documents rise from 10 to 10,000. Counterfactual retraining shows the relationship is causal. | Kandpal, Deng, Roberts, Wallace, Raffel. "Large Language Models Struggle to Learn Long-Tail Knowledge." ICML 2023. https://arxiv.org/abs/2211.08411 | Measured on factual QA, not code. Applying it to API knowledge is an inference, though a natural one: an API name is a fact with a frequency. |
| Models emit deprecated APIs 25 to 38% of the time | Deprecated usage rate (DUR) across seven models and eight Python libraries ranged 25 to 38%; larger models were not better. | Wang et al. "LLMs Meet Library Evolution: Evaluating Deprecated API Usage in LLM-based Code Completion." ICSE 2025. https://arxiv.org/abs/2406.09834 | Python only; GPT-3.5, CodeLlama-7b, CodeGen, StarCoder2 era models. The rates will differ for frontier models and for UI libraries. The direction is the durable part. |
| In-file context dominates the prior | Same study: prompts cut from outdated functions produced 70 to 90% DUR; prompts cut from up-to-date functions produced 9 to 18%. The authors attribute the gap to contextual characteristics of the surrounding code. | Wang et al., above. | Same scope. This is the strongest measured support for "sibling code is the prompt" and for codebase hygiene mattering more than published docs. |
| Version-pinned generation is hard; docs help; version labels help some | LibEvolutionEval: in-file only is the worst setting; adding a version comment "significantly enhances accuracy"; version-matched retrieved docs help most. GitChameleon 2.0: frontier models score 48 to 51% on version-pinned problems under greedy decoding; retrieval adds up to 10 points; self-debugging with execution adds 10 to 20. | Kuhar et al. "LibEvolutionEval." NAACL 2025. https://arxiv.org/abs/2412.04478. Misra et al. "GitChameleon 2.0." ACL 2026. https://arxiv.org/abs/2507.12367 | Python. Note the correction to an earlier version of this skill: a bare version label is not useless, it is just much weaker than docs. |
| Type errors are the dominant compile failure | In LLM-generated TypeScript, 94% of compile errors on average are type-check failures and 6% are syntax. Constraining decoding to well-typed programs cut compile errors by 52 to 75% and raised pass@1. | Mündler, He, Wang, Sen, Song, Vechev. "Type-Constrained Code Generation with Language Models." PLDI 2025. https://arxiv.org/abs/2504.09246 | HumanEval/MBPP-style tasks, open-weight 2B to 34B models. It measures that types catch a lot, not that library design changes what they catch. That second step is the skill's inference. |
| Vision feedback is a weak verifier for layout | On 484 real webpages, frontier multimodal models "mostly lag in recalling visual elements and generating correct layout designs" when converting screenshots to code. | Si et al. "Design2Code." NAACL 2025. https://arxiv.org/abs/2403.03163 | Measures screenshot-to-code, not self-review of a rendered result. It is indirect support for "rendering feedback is noisy," not a measurement of it. |
| Models confidently emit identifiers that do not exist | 19.7% of packages recommended across 16 models did not exist (5.2% for commercial models, 21.7% open-source); JavaScript worse than Python (21.3% vs 15.8%). | Spracklen et al. "We Have a Package for You!" USENIX Security 2025. https://arxiv.org/abs/2406.10279 | Package names, not component names. Relevant because it shows that when the prior has no sharp answer, the model invents a plausible one rather than stopping. |

## Inferred: mechanisms consistent with the measurements, not measured on UI libraries

Treat these as strong heuristics. Each has a proposed local measurement.

| Claim | Why it is plausible | How to test it on your system |
|---|---|---|
| React + TypeScript is the sharpest UI prior; shadcn/Radix grammar is the sharpest component grammar | Octoverse contributor share; React's multi-year lead in State of JS usage; v0's training statement; observed default output of frontier models. | Prompt the target model with no context for ten common widgets. Count how many first attempts use `open`/`onOpenChange`, `Root`/`Trigger`/`Content`, `variant`/`size`. |
| Closed unions beat boolean combinations for agents | Unions are enumerable in-editor and type-checked; boolean combinations that were never designed compile anyway. Mündler et al. show types catch most compile errors, so what types encode matters. | Ship the same component both ways to two branches. Measure silent-misuse rate (compiles, renders wrong) across sampled generations. |
| Regularity lets a few in-context components teach the catalog | In-context learning is pattern completion; the Wang et al. context effect shows how strongly in-file patterns steer output. | Give the model two components with the shared grammar and ask for a third that exists but is not shown. Score API correctness. |
| Names carry layout expectations (padding ownership, width behavior, spacing source) and violating them fails silently | Types cannot express visual expectation; Design2Code shows models are weak at layout even with pixels in front of them. | Render sampled output for components that break the expectation their name creates. Count layouts a reviewer flags as wrong where the code compiled. |
| Call-site magnitudes drift across files and sessions | Within one output, self-attention copies earlier choices, so drift is mostly cross-file and cross-session; the context effect above supports both halves. | Grep sampled generations for gap/padding values. Compare within-file variance to cross-file variance. |
| The catalog and examples steer generation; showcased overrides become the workflow | Agents build with what exists and is named recognizably; the Wang et al. context effect makes example style a strong steer. | Publish two doc variants (with and without `className` in canonical examples). Measure override frequency in generated code. |
| Agents plan layouts before reading code, in units like "page header" and "toolbar" | Consistent with observed transcripts: agents grep for usages and read types, rarely implementation. | Inspect agent transcripts for your repo. Record how often the agent opens component source versus types and sibling usages, and whether its plan vocabulary matches your catalog names. |
| Intent components reduce divergence | Each re-derivation of a recurring layout is a chance to diverge; an intent component collapses it to one. | Compare structural variance of "empty state" or "page header" regions generated with and without the intent component available. |

## Local protocol

1. Write 20 to 40 realistic UI tasks for your product. Sample each 3 to 5 times with the target model in three regimes: no context, types plus two sibling usages, full component source.
2. Score each sample: first-attempt compile; API misuse split into caught-by-types and silent; token or gap variance across sibling call sites; accessibility lint; a two-minute human visual pass.
3. Change one design decision (axis split, required label, layout primitive, example style). Re-run. Keep what moves the numbers.

Numbers from this protocol on your own library outrank every row above.
